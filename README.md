# GitHub Secret-Exposure Research Prototype

A Python research prototype related to identifying potential API-key exposure in public GitHub content. This project should be used only for authorized defensive research and security awareness.

## Intended defensive use

- Understand how secrets can accidentally appear in source repositories
- Test secret-handling and remediation procedures in repositories you own or are authorized to assess
- Reinforce secure configuration practices and responsible disclosure

## Technology

- Python 3
- Selenium for browser automation
- tqdm for progress reporting
- Rich for terminal output
- SQLite for local research state/results

Dependencies are listed in `requirements.txt`.

## Setup

1. Install Python 3 and Google Chrome (or a compatible browser supported by the installed Selenium version).
2. Create a virtual environment.
3. Install dependencies:
   ```bash
   python -m venv .venv
   # Windows
   .venv\Scripts\activate
   # macOS/Linux
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. Review the source and ensure the environment is configured for an authorized, limited research scope before running it.

## Important: responsible handling of findings

- Do not use, test, redeem, or share credentials belonging to other people or organizations.
- Do not collect or retain raw secret values when a redacted finding is sufficient.
- Report suspected exposures through the repository owner's approved security contact or platform reporting process.
- Prefer GitHub secret scanning and push protection for repositories you administer.
- Protect local result files; they may contain sensitive metadata. Local databases are ignored by `.gitignore` and must not be committed.
- Rotate any credentials exposed in a repository and remove them from history where appropriate.

## Data and limitations

The local SQLite database is generated by the tool at runtime and is intentionally not distributed. Search behavior, site rate limits, and platform protections can change; treat results as leads for authorized review rather than proof that a credential is valid.

This is an experimental research tool, not a replacement for GitHub secret scanning or an organization's security-response process.
